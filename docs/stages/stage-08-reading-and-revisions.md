# Stage 08：正式阅读、修订与时间线

## 目标

让审核员能在发布前修订 AI 草稿并留下不可丢失的版本记录；让读者按主题和实体连续查看正式事件。

## 已实现

- 草稿与已撤下事件支持人工编辑，已发布事件必须先撤下再修改。
- 每次保存生成递增修订号、完整内容快照、操作者、时间和修订说明。
- 人工修订后重新运行确定性发布门禁，不能通过编辑绕过引用、证据和置信度要求。
- 主题标签按事件类型受控生成；实体只从固定词典与正式来源中识别。
- `/topics`、`/topics/:slug`、`/entities`、`/entities/:slug` 仅展示已发布事件。
- 既有草稿通过迁移补齐 v1 快照、主题和已识别实体。

## 发布原则

公开信息流、详情页和时间线共用同一个 `published` 数据边界。演示事件仍有显式标记；正式事件发布后，首页优先使用正式数据。

## 验证

修订输入契约覆盖完整内容和必填说明；全量测试、Lint、构建与 D1 迁移作为阶段验收。
