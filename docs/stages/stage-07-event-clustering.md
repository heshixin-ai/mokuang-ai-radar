# Stage 07：跨来源事件聚类

## 目标

在已批准候选生成正式事件前，先判断它是新事件还是已有事件的补充来源，避免同一变化被重复发布。

## 已实现

- 确定性相似度规则：事件类型、标题与变化文本重合度、主体一致性和版本冲突。
- 三种结果：直接新建、建议合并、相似但需人工判断。
- 聚类建议持久化，重复调用保持幂等。
- 后台显示相似度、目标事件和判断原因，审核员可确认合并或保留独立事件。
- 确认合并后补充来源与引用，并重新阻断目标事件，要求人工复核后才能再次发布。
- 正式草稿创建前强制检查聚类决策，不能绕过。
- 既有事件与候选关系迁移回填。

## 安全边界

- 规则不自动把不确定候选写入公开事件。
- 版本号冲突优先保留为独立事件。
- 合并不会改写原稿正文，只补充证据并触发质量复核。
- 所有建议和人工决定均保留操作者、时间和备注。

## 验证

`tests/clustering.test.ts` 覆盖高相似合并、版本冲突和不同类型隔离；全量测试、Lint、构建与迁移共同作为阶段验收。
