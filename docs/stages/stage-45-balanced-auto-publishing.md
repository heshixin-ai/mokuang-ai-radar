# 阶段 45：平衡自动发布门禁

## 目标

在不取消证据门禁的前提下，减少可信官方低风险事件因模型保守标记而积压，使当天情报更及时。

## 策略调整

- 自动发布最低置信度由 `0.8` 调整为 `0.7`。
- 自动发布仅覆盖模型发布、API 变化和研究三类低风险事件。
- 官方来源以及研究类的一手研究来源可以进入自动发布流程。
- 单纯的模型 `needs_review` 或旧版 `confidence_below_0_8` 标记，不再阻塞置信度达到 `0.7` 的可信低风险草稿。
- 引用缺失、证据不足、受影响角色缺失、来源不可信、聚类冲突及低于 `0.7` 仍会阻塞。
- 价格、政策、融资等高风险类型继续要求人工处理。

## 审计与兼容

- 自动流程放行旧版软阻塞草稿时，发布动作会保留放行前的质量状态和问题快照。
- 发布成功后将事件质量状态归一为 `ready`，清除仅用于阻塞的软标记。
- 手工发布接口不获得放宽权限，仍要求草稿原本为 `ready`。
- 自动发布队列会重新读取已有的阻塞草稿，使历史积压可以按新策略再次判断。

## 验证

- 单元测试覆盖 0.7 边界、硬风险阻塞、软标记放行和自动发布审计参数。
- 全量测试、代码检查和生产构建通过后部署。
