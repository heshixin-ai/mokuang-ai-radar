# 第 17 阶段技术开发文档｜保守自动发布

> 配套文档：`mokuang-prd.html`、《AI 产品 Vibe Coding 通用技术栈手册》与《技术适配声明》。本文档只覆盖第 17 阶段。

## 一、阶段目标

- 交付范围：在已有“采集 → AI 候选 → 聚类 → 草稿 → 质量门禁 → 发布”状态机上，增加可关闭的保守自动发布。
- 阶段产物：确定性候选策略、草稿二次门禁、受保护的批处理接口、外部调度器串联、审核与发布审计。
- 验收标准：官方来源、置信度不低于 0.90、无风险标记、非高风险主题、聚类无歧义且草稿质量为 `ready` 时才能自动发布。
- 明确不做：不自动合并相似事件；不自动发布价格、政策、融资、媒体单一来源、模型升级路由或任何要求复核的内容。
- 主链路：待处理候选 → 确定性策略 → 可审计批准 → 聚类无歧义 → 真实模型草稿 → 二次门禁 → 发布审计 → 首页可见。

## 二、技术适配摘要

- 延续全栈 TypeScript、D1 持久化和现有固定状态机，不引入第二套后端或任务队列。
- 开发路径：后端先行。本阶段改变发布策略和调度链路，不改首页交互。
- 模型只负责结构化候选与草稿；是否发布由后端规则、状态机和权限共同决定。

## 三、技术栈与模型

- Vinext / Next.js 兼容运行时、TypeScript、Zod、Cloudflare D1。
- DeepSeek V4 Flash 为主模型；发生升级路由的候选默认不自动发布。
- 不新增依赖。

## 四、环境与配置

- `AUTO_PUBLISH_MODE=off|safe`：默认 `off`，生产验收后设为 `safe`。
- `AUTO_PUBLISH_MIN_CONFIDENCE=0.9`：可配置范围 0.8–1.0。
- `AUTO_PUBLISH_BATCH_SIZE=1`：单次最多处理 1 个候选，可配置上限为 3。
- 审核 Token、Sites 绕过 Token 与模型 Key 继续由托管 Secret 保存。

## 五、项目结构

- `lib/events/auto-publish-config.ts`：安全默认和配置校验。
- `lib/events/auto-publishing.ts`：候选规则、草稿二次门禁与固定编排。
- `lib/repository/auto-publishing.ts`：只读扫描可恢复的待处理候选。
- `app/api/v1/admin/auto-publish/route.ts`：受审核自动化身份保护的批处理入口。

## 六、数据、资产与状态

- 不新增数据表；复用 `event_candidates`、`candidate_clusters`、`events`、`review_actions`、`publication_actions` 和 `event_revisions`。
- 中途失败时，已完成的批准、聚类、草稿状态保留在 D1；下次从当前状态继续。
- 合并建议、质量阻断草稿不反复消耗模型，保留在人工工作台。

## 七、API / 工具设计

- `POST /api/v1/admin/auto-publish`
  - 认证：复用 `REVIEW_AUTOMATION_TOKEN` 或已授权审核身份。
  - 请求体：无，不允许调用方传入阈值、来源、候选 ID 或批量。
  - 响应：只返回扫描、候选、尝试、发布、延后和失败计数及不含正文的内部 ID。
  - 错误：`REVIEW_AUTH_REQUIRED`、`REVIEW_ACCESS_DENIED`、`AUTO_PUBLISH_CONFIG_INVALID`、`AUTO_PUBLISH_FAILED`。

## 八、Prompt 设计

- 不修改 G-01 / P-01 至 P-04。
- 自动发布不增加模型“自主决策”提示词，全部采用确定性后端规则。

## 九、验收界面或纵向切片

- 不新增页面。首页继续只读取 `published` 事件，审核工作台继续展示延后候选、聚类建议和阻断草稿。

## 十、测试要求

- Mock 自动化：默认关闭、安全候选通过、媒体/高风险/低置信/要求复核/升级路由阻断、聚类建议延后、草稿二次门禁、批量上限、审计身份。
- 真实模型冒烟：用一条已存在的官方高置信候选跑通草稿生成、质量门禁、正式发布和首页可见。
- 真实生产数据不由测试删除或回退。

## 十一、验收清单

- [ ] 生产环境未配置 `safe` 时，调用不会批准或发布任何内容。
- [ ] 官方高置信候选自动发布后，首页数量增加，详情页存在官方来源和引用。
- [ ] 高风险候选仍保持待人工处理，不出现在首页。
- [ ] `review_actions` 与 `publication_actions` 能看到自动化身份和策略说明。
- [ ] 外部定时工作流先刷新来源，再调用安全自动发布。

## 十二、风险与待确认项

- 自动发布会产生真实外部可见内容。通过默认关闭、官方来源、高阈值、双重门禁、小批量和审计降低风险。
- 生产发生单个重大错误时，立即将 `AUTO_PUBLISH_MODE` 改回 `off`，撤下事件并恢复全量人工审核。
- 需要产品经理决定的问题：无，PRD 已明确 A 级官方源通过门禁后可自动发布。

## 十三、交接给下一阶段

- 生产验收后，下一阶段只需解决可靠外部 Timer 和积压分析吞吐，不再修改发布安全边界。
