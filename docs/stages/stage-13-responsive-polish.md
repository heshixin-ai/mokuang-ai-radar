# Stage 13 · 首页响应式与情报区优化

## 目标

针对线上首页在桌面、平板和手机尺寸下的实际表现，修正中等屏幕布局、情报筛选和锚点访问问题。

## 浏览器检查结论

- 页面没有脚本错误、请求失败或整页横向溢出。
- 740–768px 宽度仍展示完整桌面导航，信息密度偏高。
- 三张产品价值卡在平板双列布局中留下半屏空位。
- 只有两条事件时，桌面三列网格留下空列。
- 没有事件的分类仍可点击，容易进入没有内容的状态。
- 直接访问 `/#events` 时，首轮布局完成前可能无法准确定位情报区。
- 手机筛选按钮需要横向滚动，结尾 CTA 标题换行不自然。

## 本阶段完成

- 860px 以下隐藏完整导航并优化首屏字号、段落宽度和留白。
- 平板端第三张价值卡改为整行展示。
- 事件网格按实际事件数自动填充可用列。
- 筛选按钮显示数量，无数据分类自动禁用。
- 手机筛选改为三列两行，所有分类无需横向滚动即可看见。
- 直接打开 `/#events` 会在布局稳定后准确定位到情报区。
- 收紧预览、内容区和 CTA 的纵向间距，修正手机端 CTA 换行。

## 验证范围

- 1440px 桌面
- 768px 平板
- 740px 临界宽度
- 390px 手机
- 全尺寸均无整页横向溢出、控制台错误或失败请求
