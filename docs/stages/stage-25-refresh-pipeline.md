# 第 25 阶段技术开发文档｜实时更新与中国来源修复

## 阶段目标

- 修复来源轮询、AI 分析和自动发布吞吐量不匹配造成的事件更新延迟。
- 补充能覆盖千问、Kimi、智谱、MiniMax、DeepSeek、万相等国内模型的官方更新来源。
- 避免历史 Release 长期占用分析队列，优先处理近期和中国来源事件。

## 实现结果

- 受控来源由 20 个增加到 21 个，新增阿里云百炼“模型上下架与更新”官方页面。
- 新增固定白名单表格解析器，按发布日期和模型 ID 去重，保留官方链接与必要短摘录。
- 每轮最多检查 30 个到期来源，足以覆盖当前全部来源；来源并发提升到 5。
- 每轮 AI 分析上限提升到 10，最近 14 天之外的未处理文档自动退出待分析队列。
- 待分析顺序优先 DeepSeek、阿里云百炼和 Kimi，再按发布时间处理其他来源。
- 自动发布批次上限扩展到 10，生产推荐值为每轮 5 条；原有官方证据、质量与风险门禁保持不变。
- 外部刷新请求超时提升到 4 分钟，GitHub 工作流最长执行时间提升到 8 分钟。

## 验证

- 单元测试覆盖阿里云四列/五列表格、跨部署范围重复记录去重和中国来源登记。
- 使用真实阿里云官方页面验证，成功解析 10 条最新模型更新，包括 Kimi K3、GLM-5.3、MiniMax H3、Qwen3.8-27B 与 Wan3.0-Video-Prime。
- `npm test` 与 `npm run build` 均通过。

## 运行边界

- GitHub Actions 的定时任务可能延迟或丢弃，因此“每 5 分钟”是请求频率，不是严格 SLA。
- 自动发布仍使用确定性安全门禁；不需要人工逐条审核，但证据不足、冲突或高风险内容不会自动上线。
